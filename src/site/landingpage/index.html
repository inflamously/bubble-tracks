Small loops that close

A bubble is one task. It ends, you see it end, and the track shows how far you are from Finish.

?

Fog stops the agent

Unclear steps stay fog. The agent does not plan them on its own, and a hook blocks file edits while it stands on one.

◐

You steer after every bubble

The agent pauses when a bubble is done. Reorder, insert, remove, or turn a bubble back into fog before it moves on.

A track has rules before it has code.

plan

Plan mode, made easy

Say the goal in chat. The agent drafts the whole track and shows it in one fixed shape, TL;DR first. Change anything and it shows the plan again. Nothing is created until you say go.

guard

Guards put rules into the track

A guard says what not to do or touch. The agent reads the guards before it acts, and a guard holds even when you later ask for something it rules out.

[Boundary: …]

A boundary scopes every bubble

Each bubble names the places it may touch: files, or whatever else the work is made of. The work stays small and easy to review.

Four kinds of fog

Not every unknown is the same. Naming the kind of fog tells you who should clear it, and how.

The types are a convention you and the agent follow. No code enforces them.

known-known
You know what to build and how. You write the plan for the bubble.
known-unknown
You know the question but not the answer. You and the agent work it out together.
unknown-known
The answer is in your head, but you have not said it yet. The agent helps you pull it out.
unknown-unknown
Too much is open to plan at all. The agent interviews you first.

Ownership gives control back. You choose who does each bubble.

agent

The agent does every bubble

The default. You plan the fog and steer after every bubble. The agent does the work.

hybrid

You take the bubbles you want

Pick single bubbles to do yourself, at any time. The agent does the rest.

user

You do every bubble

The agent hints at the steps, waits, and checks your work against the bubble's boundary and the guards.

One track is the start. Bigger work gets more of them.

bubble fork

Split a bubble into its own child track. The parent waits until the child is done.

bubble diverge

Open a side track for the idea that showed up mid-task, without derailing the main one.

bubble research

Gather sources for one bubble before anyone writes code for it.

bubble abilities

Reusable workflows, kept as Markdown files, that run against a bubble or a whole track.

Tracks are plain JSON in .bubble-tracks/, so they live in your repo and show up in your diffs. A closed track is read-only.

Install

Claude Code

/plugin marketplace add inflamously/bubble-tracks
/plugin install bubble-tracks@bubble-tracks

Then add the status line by hand. Plugins cannot set it for you.

Codex CLI, Gemini CLI, or any agent that reads AGENTS.md

node install.js codex gemini agents-md --project /path/to/your/repo

Run it from a checkout. The installer backs up every file it changes to *.bak.

Needs Node.js 18 or newer. No npm runtime dependencies. MIT licensed.

Honest limits

  • The fog gate blocks file-edit tools. It does not block shell writes.
  • With AGENTS.md alone the gate is soft: the model is told to stop, nothing forces it.
  • The live status line works in Claude Code. Codex and Gemini use bubble show.
  • Hook paths are absolute. Teammates re-run the installer after cloning.
